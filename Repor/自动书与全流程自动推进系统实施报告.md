# MoreAIPlayer「自动书」与全流程自动推进系统实施报告

> 交接对象：后续实现 agent
>
> 文档性质：需求冻结、架构设计、实施顺序与验收合同。除非遇到无法编译的外部 API 变更，不要中途向用户追问；按本文已经作出的决定实施。
>
> 目标版本：以当前工作区实际引用的 tModLoader/Terraria 程序集为唯一 API 权威。联网资料用于梳理游戏流程，不得用网页里可能属于 Terraria 1.4.5 的新行为覆盖当前本地 1.4.4 系列运行时事实。

## 0. 结论先行

这项功能可做，但不能把它实现成一个越来越长的 `if (downedBoss)` 脚本。可维护且有机会真正跑到结局的实现必须由五层组成：

1. **独立的自动伙伴身份与存档**：外观、名字、装备栏、背包继续复用普通 `CompanionProfile`，另挂自动流程状态；同一角色、同一世界只允许一个。
2. **世界知识缓存**：分帧扫描世界中的宝箱、矿物、水体、危险物、Boss 入口和关键设施，提供“透视”信息，但不直接移动或生成物品。
3. **双轴进度模型**：世界已经解锁到哪里，与伙伴自己拥有的镐力、装备、机动性、药水和材料分别计算。
4. **目标/前置任务图**：规划器根据缺口选择砍树、合成、建房、探索、挖矿、钓鱼、购物、建场地或打 Boss；失败后切换合法替代路线。
5. **仍受 Terraria 物理约束的执行器**：允许全图知识、零延迟决策和完美瞄准，不允许飞天、穿墙、凭空刷物品、无条件传送或直接写 Boss 击败标记。

第一版的正式完成范围是**普通世界中的原版月亮领主主线**。模组材料、模组门、模组武器可以通过通用属性自然工作；模组 Boss/模组主线必须走明确的扩展适配器，不得假装能从任意模组自动推导出完整流程。特殊世界种子如果没有对应策略，应进入可诊断的 `BlockedUnsupportedWorld`，不能乱改世界。

## 1. 用户合同（不可自行改写）

### 1.1 自动书

- 新物品名：**自动书**。
- 定位：独立娱乐道具，和猎人书、倍率书一样不属于普通伙伴的指挥/建造体系。
- 左键：召唤自动伙伴。
- 同一角色、同一世界最多存在一个自动伙伴；已有活动实例时再次左键只提示“已经在运行”，不得重置、刷新、替换、传送或再生成一个。
- 自动伙伴暂时不活动但存档存在时，左键重新召唤原来的实例状态，不生成新名字、不清空背包。
- 右键：直接打开这个自动伙伴的普通伙伴背包 UI。
- 右键时尚未创建/召唤过该伙伴：只显示本地化提示，不顺带召唤。
- 单人模式限定，沿用项目当前“虚拟 Player”边界。
- 图标固定使用尚未被当前六本书占用的 `ItemID.LunarFlareBook` 原版贴图；如果当前本地 API 中该常量不存在，唯一回退是 `ItemID.SpellTome`，不要再询问用户。
- 配方沿用娱乐书惯例：1 个泥土块直接制作。

### 1.2 独立性

自动流程未完成前：

- 不跟随主人，不响应主人受伤护驾，不接收指挥书路点，不加入普通模式轮盘，不参与建造书三战术，不参与普通小队站位。
- 不主动看主人、接近主人、保护主人、从主人背包拿材料或从主人私人箱子拿东西。
- 不攻击真实玩家，也不会对真实玩家造成弹幕、接触或 PvP 伤害。
- 真实玩家的武器、弹幕、鞭子不能伤害或增益它。
- 主人唯一允许的直接互动是通过自动书右键查看/编辑它的背包；玩家拿走了关键物品后，自动伙伴只把它视作资源减少并重新规划。
- 它使用世界公共进度，所以其 Boss 击杀会真实推进当前世界，NPC、事件和困难模式变化也会影响主人。这正是娱乐效果，不得做成私有模拟世界。

击败月亮领主后：

- 清除自动身份和自动规划状态，保留名字、外观、装备、背包、饰品、工具与染料。
- 该 `CompanionProfile` 转成普通幻影伙伴，之后才加入指挥书、建造书、普通小队和主人跟随体系。
- 转换后的生命/魔力回到普通伙伴现有规则（跟随主人有效上限），不继续保留自动流程独立生命成长规则。
- 自动书对该世界标记为完成；再次左键不能再创建第二个自动伙伴。

### 1.3 合法优势与禁止项

允许：

- 读取整个世界的 tile、chest、NPC、item、projectile 和世界进度标记。
- 每帧重新决策；完美知道敌人、陷阱和弹幕的位置、速度、伤害与预计碰撞。
- 完美瞄准和合理提前量。
- 比人更快地在背包内合成、整理、换装和选择武器。
- 根据底层机制精确判断房屋是否合法、鱼池大小、配方、镐力、Boss 召唤条件与装备强弱。

禁止：

- 飞天、穿墙、无条件瞬移、锁血、无敌、直接删除敌人、直接写 `downed` 标记。
- 凭空生成装备、弹药、钱币、药水、Boss 召唤物或建筑材料。
- 不消耗材料直接合成、放置或购买。
- 绕过镐力、钥匙、事件和区域门槛。
- 为了“保证通关”在卡住时悄悄作弊。找不到合法路线时应进入阻塞状态并周期性重试。

### 1.4 死亡、复活与走位

- 普通状态死亡后 60 tick（1 秒）复活。
- `Main.ActiveNPCs` 中存在有效 Boss 时，死亡后 300 tick（5 秒）复活。
- 仅自动伙伴使用这组时间；不要修改普通伙伴目前的复活常量。
- 复活位置：有当前 Boss 场地检查点时回到已验证安全的场地检查点；否则回到自己的避难所出生点；都无效时回到世界出生点附近的安全落点。
- 死亡不掉落物品和钱币，任务不清空；当前战斗可因 Boss 消失而失败并重新准备。
- 自动伙伴的危险控制器决策延迟固定为 0，但移动仍只能使用当下真实具备的跑、跳、额外跳、冲刺、翅膀、坐骑和钩爪能力。

## 2. 当前项目落点审计

### 2.1 可直接复用

- `Companion/Content/CompanionHunterBook.cs`、`PlayerScaleBook.cs`：娱乐书的左/右键和单人检查样板。
- `Companion/Content/CompanionDebugger.cs`：普通 profile 创建与 `CompanionEntitySystem.Summon` 的样板。
- `Companion/CompanionProfile.cs`：名字、外观、10 格武器栏、6 格弹药、护甲、饰品、40 格背包、网、钓竿、钩爪和坐骑的持久化容器。
- `Companion/CompanionEntitySystem.cs`：虚拟 `Player` 槽位、ItemCheck/弹幕上下文、伤害、释放与异常隔离。
- `Companion/UI/CompanionUISystem.cs`：按 companion slot 打开背包。
- `Companion/AI/CompanionNavigator.cs` 与 `CompanionPathfinder.cs`：局部寻路、平台、开关门、跳跃和普通地形移动基础。
- `Companion/AI/CompanionThreatAvoidance.cs`：危险预测候选动作与弹幕/NPC 风险函数基础。
- `Companion/AI/CompanionBrain.cs`：真实 ItemCheck 攻击、采矿、砍树、钓鱼、武器选择、钩爪和移动执行基础。
- `Companion/Building/CompanionBuildingSystem.cs`：消费真实材料并放置方块/墙的基础。
- `Companion/CompanionFaultGuard.cs`：新自动系统每个大执行通道都必须接入相同的故障隔离。

### 2.2 不能直接套用的现状

- 普通 `CompanionBrain` 的目标始终围绕 owner/mode；自动伙伴需要单独的 `AutoCompanionBrain`，不能把几十个自动阶段塞进普通脑。
- 普通伙伴当前生命/魔力上限跟随主人。自动伙伴从“新角色”成长，必须在自动身份期间使用 profile 自己的生命水晶、生命果和魔力水晶计数。
- 普通伙伴明确不会主动拾取世界掉落；自动伙伴必须有**仅对自动身份开放**的目标掉落收集器，不得改坏普通伙伴合同。
- 当前 inventory 映射借用了四个 coin slot：50–51 是额外弹药，52 是捕虫网，53 是钓竿。自动伙伴仍可把钱币放在 10–49 的背包映射区，但任何“钱币总额/购物”逻辑都不能假设钱只在原版 coin slot。
- 当前 Mining/Fishing 是主人示范或模式驱动，只能局部找目标。自动流程需要全局目标选择后再复用局部 ItemCheck 执行。
- 当前 `CompanionThreatAvoidance` 有 3–8 tick 人类式反应和 5 tick 扫描间隔；自动伙伴不能改这份共享参数，而应使用零延迟配置或独立 `AutoThreatController`。
- 当前 `CompanionEntitySystem.CountActiveOwnedBy`、`CompanionCommandBook.OwnedActiveCompanions`、建造战术和小队排序会把所有普通实例算进去。所有这些入口都要根据 `profile.IsAutoRunning` 过滤；完成转换后过滤自然解除。

在 `Companion/Automation/` 下新增独立子系统：

## 4. 身份、唯一性与存档

### 4.1 一世界一伙伴

`CompanionPlayer` 保存一个以 world unique ID 为键的自动 profile 绑定表：

- 值为 `ProfileId`、`Created`、`Completed`、自动状态数据版本。
- 新世界第一次左键时创建普通 `CompanionProfile`，随机名字和外观，写入两件初始工具。
- 同一角色切换到另一个世界会得到另一个从零开始的自动 profile，避免把月亮领主装备带进新世界直接跳过流程。
- 旧世界重进后复用该世界对应 profile。
- 世界文件复制导致 unique ID 改变时按新世界处理。

### 4.2 初始物品

只给予：

- 1 把 Copper Pickaxe，放入保留镐位。
- 1 把 Copper Axe，放入第一个普通可用栏位。

不送短剑、木材、药水、钱币、火把、鱼竿、虫网、召唤物或任何护甲。所有后续物品必须来自采集、掉落、宝箱、钓鱼、购买或合法合成。

### 4.3 自动状态必须保存

- 当前 `WorldMilestone` 与 `CapabilityTier` 只作缓存，加载时重新计算。
- 当前高层目标、任务和子步骤。
- 任务开始 tick、上次取得真实进展 tick、连续失败次数、被拉黑目标及过期时间。
- 避难所区域、工作区点、出生/复活点、专属储物箱坐标。
- 已经检查/取过目标物品的自然箱子坐标。
- 生命水晶、生命果、魔力水晶的个人消耗计数与独立基础上限。
- 世界扫描游标、已发现的稳定兴趣点；tile 数据变化后允许重新验证。
- 自动流程版本号。版本迁移失败时保留 profile 物品，重建任务与扫描缓存，绝不能清空装备。

## 5. 双轴进度与规划器

### 5.1 世界里程碑

原版提供器至少识别：

1. 新世界/未击败 Boss。
2. Eye of Cthulhu。
3. Corruption/Crimson 主 Boss。
4. Goblin Army 与 Goblin Tinkerer 是否可用。
5. Skeletron。
6. Wall of Flesh / `Main.hardMode`。
7. 三个机械 Boss（分别记录）。
8. Plantera。
9. Golem。
10. Lunatic Cultist。
11. 四柱（分别记录）。
12. Moon Lord 完成。

读取本地运行时的 `NPC.downed...`、`Main.hardMode`、入侵和特殊世界字段；不要按网页拼字段名。其他玩家先推进了世界时，下一次规划必须立即同步跳过已经完成的世界目标。

### 5.2 个人能力

能力不是“背包里出现某个固定 ItemID”，而是基于实际物品属性：

- 工具：最高 pick power、axe power、hammer power、tile/wall reach。
- 生存：有效防御、最大生命、生命恢复、可用治疗总量、debuff 免疫。
- 机动：跑速、加速、额外跳、免摔、钩爪、冲刺、翅膀/飞行时间、熔岩/火块保护。
- 输出：按目标防御估算的单体 DPS、群体/穿透能力、射程、弹道是否受墙阻挡、弹药续航、召唤持续输出。
- 建造：实心块、平台、墙、火把、篝火、家具、箱子库存。
- 钓鱼：钓竿强度、鱼饵总量、鱼池质量和目标 crate 路线。
- 制作：当前可达工作站集合和材料闭包。
- 经济：所有背包位置中的铜币等价总额。

装备选择不锁死职业。官方职业配置指南也强调 Terraria 没有正式职业锁定、跨职业强力武器和混合配置是合理的；因此实现应为“当前实际持有物的评分器”，而不是强迫一次随机选定职业后永不改变。[官方职业配置指南](https://terraria.wiki.gg/wiki/Guide%3AClass_setups)

### 5.3 目标图而非线性脚本

每个目标声明：

- 世界前置。
- 个人能力前置。
- 消耗预算。
- 可用路线（Plan A/B/C）。
- 成功谓词。
- 硬失败、软失败与重试冷却。
- 是否允许中断。

例：`AcquireRunningBoots` 的成功谓词是装备或背包中存在任何具有等价奔跑能力的饰品，而不是只认 Hermes Boots。路线依次为：已知宝箱直接取 → 扫描未检查的 Underground/Ice/Desert Cabin 箱 → 建钓鱼条件并钓 Wooden/Iron 或生物群落 crates → 长时间没有结果时继续其他可并行成长目标，稍后重试。Sailfish Boots 确实来自 Wooden/Iron Crates，可作为没有跑鞋宝箱时的合法替代。[Sailfish Boots](https://terraria.wiki.gg/wiki/Sailfish_Boots)

## 6. 世界透视与性能预算

### 6.1 扫描对象

- `Main.chest`：坐标、箱型、锁定状态、目标物品摘要。
- 地表树、树苗可种植点、岩石/土堆 bait 物件。
- 矿簇：铜/锡、铁/铅、银/钨、金/铂、邪恶矿、陨石、狱石、三档困难矿、叶绿矿。
- 生命水晶、生命果、落星。
- 恶魔/猩红祭坛、暗影珠/猩红心脏。
- 地牢入口和老人、蜂巢/幼虫、地狱连续走廊候选。
- Plantera Bulb、神庙门、Lihzahrd Altar、Power Cell 来源。
- 水面与连通液体体积、所处高度层、生物群落。
- 陷阱方块、压力板、炸药、巨石、危险液体、伤害 tile、尖刺。
- 玩家或自动伙伴放置的工作站、自动伙伴专属房屋与箱子。

### 6.2 分帧与缓存

- 绝不在一个 tick 扫完整世界。
- `Main.chest` 可低频完整扫描；tile 世界按固定预算（建议 4096–8192 tiles/tick）条带扫描。
- 每 tick 自动系统总 CPU 预算目标 2 ms，硬上限 4 ms；超过即保存游标并让出。
- 大型矿簇只保存包围盒、代表点、估算剩余量，不保存每一块矿的永久列表。
- 到达目标前重新验证实际 tile/chest；缓存只说明“曾经发现”，不能授权操作不存在的对象。
- 自动伙伴自己挖掘/建造后，局部矩形立即标脏；其他模组大范围改世界时，周期性抽样发现不一致后重扫区域。

## 7. 导航、采集和真实动作

### 7.1 分层导航

现有 A* 继续作为局部 100–200 tile 范围导航器。跨世界旅行增加粗层：

1. 兴趣点之间的直线/地表/洞穴粗路线。
2. 局部 A* 走现成通道。
3. 没有通道时，规划有限长度的合法挖掘走廊、平台桥、绳索或落脚点。
4. 每个动作边附带危险、耗材、时间和回程成本。

禁止把世界透视等同于瞬移。远处目标只能通过实际移动到达。普通卡住恢复先重新寻路、换入口、挖替代通道、放平台；最后只能放弃该目标并选替代路线，不能把自动伙伴传到目标旁边。

### 7.2 采矿与砍树

- 复用真实工具 ItemCheck 路径；只在真实 reach 内挥工具。
- 目标矿簇按“从可接近边界到内部”的顺序挖，不能隔墙远程删除。
- 保护箱子、祭坛、神庙砖、地牢砖、Boss 召唤物件和 frame-important 设施，除非当前明确任务、工具与世界阶段允许操作。
- 砍树后等待实际掉落被拾取，再在原树根附近验证地面和空间并消耗对应树苗补种。
- 每棵被自动伙伴完整砍掉的普通树，至少尝试补一棵；没有树苗时记录欠种点，获得树苗后回补。地形已被玩家改坏则放弃该点，不强改玩家建筑。
- Worm 可由打碎 rock/dirt piles 产生；这条用户指定路线是原版合法机制。[Worm](https://terraria.wiki.gg/wiki/Worm)

### 7.3 掉落与宝箱

- 新增自动伙伴专用拾取例外，普通伙伴仍不得自动捡世界物品。
- 只对当前任务需要、升级评分为正、弹药/药水/材料白名单或自己击杀产生的物品寻路拾取；不为每个垃圾掉落执行全图 A*。
- 自然箱子只拿当前/未来明确需要的物品和钱币，不清空装饰品与无关收藏品。
- 箱子必须在真实交互距离、未锁或持有正确钥匙时才能转移物品。
- 自有避难所箱子坐标写入状态；只有这些箱子可作为长期仓库。绝不把任意玩家箱子当仓库。
- `Chest.FindChest` 需要箱子左上角，任意箱子 tile 先通过 TileObjectData 找 top-left，再访问 `Main.chest`。[tModLoader Chest 文档](https://docs.tmodloader.net/docs/preview/class_chest.html)

### 7.4 快速合成

- “快速”指不播放人类 UI 操作延迟，不代表绕过配方。
- 根据 `Main.recipe`/本地配方注册结果动态寻找产物，不复制一份硬编码配方表。
- 必须验证自动伙伴自己的材料、附近真实工作站、液体/生物群落/世界条件。
- 实际扣除材料，并调用 RecipeLoader 的消费与 OnCraft 链，保证模组配方修改、材料消费规则和成品 hook 能运行。相关稳定接口包括 `RecipeAvailable`、`ConsumeIngredient/ConsumeItem` 和 `OnCraft`。[RecipeLoader 文档](https://docs.tmodloader.net/docs/stable/class_recipe_loader.html)
- 配方组必须接受铁/铅、金/铂、邪恶世界材料等替代，不写死单一世界变体；Recipe 本身提供 recipe group 支持。[Recipe 文档](https://docs.tmodloader.net/docs/stable/class_recipe.html)
- 一次只完成一个配方步骤，产物入包失败则不消耗；多步合成先计算空间与中间材料。

### 7.5 NPC 与购买

- 自动伙伴必须走到目标 NPC 身边且 NPC 活着、可交互。
- 商店内容和价格在自动伙伴的虚拟 Player 上下文中用本地实际商店逻辑生成，不能自己抄一张价格表。
- 从自动伙伴背包所有格子统计并扣除真实钱币；不能借主人钱。
- 第一批白名单购买：Merchant 的 Bug Net、必要时 Iron/Lead Anvil；Goblin Tinkerer 的 Rocket Boots、Tinkerer's Workshop、Grappling Hook；后续只为计划明确需要的物品扩展。
- Merchant 出现依赖空房和玩家群体持有 50 silver；房屋和自动伙伴钱币条件都要真实满足。Bug Net 的原版价格为 25 silver。[Town NPCs](https://terraria.wiki.gg/wiki/Town_NPCs) [Bug Net](https://terraria.wiki.gg/wiki/Bug_Net)
- 解救 Bound Goblin 使用原版交互/变身路径并验证 Goblin Army 已完成；不要直接生成 Goblin Tinkerer。Goblin Army 解锁 Tinkerer's Workshop、Rocket Boots 和重铸，是核心但不属于最终 Boss 硬门槛。[Goblin Army](https://terraria.wiki.gg/wiki/Goblin_Invasion)

## 8. 避难所、NPC 房与仓库

### 8.1 建造地点

- 以世界出生点为中心，在左右各 120 tiles 内扫描平坦、安全、非邪恶、非液体、非玩家已建房区域。
- 与任何已有箱子/工作站密集区保持至少 30 tiles，避免盖到玩家家上。
- 找不到时扩大到 240 tiles；仍找不到则先做最小地形整理，不铲平大型结构。

### 8.2 初始模板

- 一个自己的工作/仓库房，内含 Work Bench、Furnace、Anvil、至少两个自有 Chest、火把和 Campfire。
- 三个独立有效 NPC 房，供 Guide、Merchant 和后续早期 NPC；需要更多 NPC 时按同模板扩建。
- 每室建议外框 10×6 tiles，完整安全背景墙、平台或门、光源、Work Bench/桌面和 Chair；建完后必须调用本地原版房屋有效性检查，不以“看起来像房子”作为成功。
- 官方房屋规则要求封闭 frame、安全背景墙、60 至少/750 以下总 tile，并具备光源、桌面、舒适物和门类设施；Torch + Work Bench + Chair + Wood Platform 是最小易得组合。[房屋规则](https://terraria.wiki.gg/wiki/Valid_house)
- 自有箱子分为：材料、装备消耗品。箱满时先压栈、卖明确垃圾、扩建第三箱；绝不删除物品腾格。

### 8.3 初始资源阈值

第一轮收集目标（不是永久上限，规划器可追加）：

- 木材 450。
- 石块 120。
- Gel 40。
- 平台库存 200。
- 火把库存 50。
- Campfire 3。

这些库存覆盖工作台、基本武器、房屋、墙、平台与探索消耗。工作台是第一座工作站；Furnace 和 Iron/Lead Anvil 构成早期金属制作链。[Crafting stations](https://terraria.wiki.gg/wiki/Crafting_station)

## 9. 钓鱼替代路线

### 9.1 触发条件

以下任一成立时启用：

- 已扫描的自然箱没有任何等价跑鞋。
- 目标矿/锭短缺且 crate 是合理替代。
- 需要特定鱼类药水材料。
- 当前危险区域采集成本显著高于钓鱼。

### 9.2 准备链

1. 先从表面箱找 Can Of Worms；它固定给普通 Worm，并可能给更高级 bait。[Can Of Worms](https://terraria.wiki.gg/wiki/Can_Of_Worms)
2. 没有 bait 时，购入 Bug Net，寻找雨天 Worm 或打碎 rock/dirt piles，再真实捕捉。
3. 制作 Wood Fishing Pole；有铁/铅时升级 Reinforced Fishing Pole。钓竿必须与 bait 同时存在。[Fishing poles](https://terraria.wiki.gg/wiki/Fishing_poles)
4. 全图缓存水体，优先 300 格有效水体；75 以下视为不可用，75–300 之间按实际惩罚评分。原版鱼池惩罚在这个区间连续变化。[Fishing](https://terraria.wiki.gg/wiki/Fishing)
5. 实际走到池边，复用现有 bobber/ItemCheck 逻辑，不直接抽奖生成渔获。

### 9.3 跑鞋停止条件

- 获得 Hermes、Flurry、Dunerider、Sailfish 或任何经属性检测等价的奔跑饰品即停止该目标。
- Wooden/Iron Crates 能出 Sailfish Boots；开 crate 必须走物品右键/掉落链，不能直接从 loot table 取结果。[Sailfish Boots](https://terraria.wiki.gg/wiki/Sailfish_Boots)
- 连续 20 分钟没有目标结果不是硬卡死：挂起跑鞋目标，继续生命、矿物或 Boss 准备，之后带更高鱼力回来。

## 10. 完美反应、陷阱与战斗

### 10.1 自动危险控制器

- 每 tick 扫描，不使用普通伙伴 5 tick 间隔和人类反应倒计时。
- 读取所有 hostile projectile 的当前位置、速度、extraUpdates、命中框和伤害，进行连续线段扫掠，避免高速弹幕跨过离散采样。
- 对 NPC 预测接触盒，对滚石/飞镖/长矛/火焰等陷阱同时考虑触发源和已生成弹幕。
- 地图透视提前把压力板、炸药、巨石和接线陷阱设为高成本；优先绕开或从安全方向拆除。真的触发后，在下一 tick 从当前真实动作候选中选择风险最低项。
- “完美”只表示输入决策及时且信息完整，不保证物理上必定躲开。所有候选都会被击中时，选择预期伤害最低、不会落入更坏地形的一项。

### 10.2 战斗装备评分

- 每个 Boss 策略给出需要的能力阈值，不固定唯一武器。
- 评分至少考虑：目标防御后的伤害、攻速、弹道速度、射程、命中率、穿透、墙体阻挡、弹药/魔力续航、召唤持续输出、护甲套装和饰品联动。
- 同阶段拿到明显更强的跨职业武器可立即换用。
- 进入 Boss 战前确保治疗药水、常用 buff、弹药/魔力和场地库存达到策略预算；失败后重新评估，不无脑原地重复召唤。

### 10.3 与玩家隔离

- 自动伙伴的攻击目标过滤真实 Player、普通伙伴和 Hunter 实例。
- 自动伙伴拥有的 projectile 对 Player/PvP 一律返回不可命中。
- 来自真实 Player 或其 projectile 的自动伙伴伤害一律拒绝；环境、敌对 NPC、敌对 projectile、坠落、熔岩和陷阱正常伤害。
- 不接收鞭子 buff。

## 11. 原版全流程任务清单

这不是要求每局严格按同一装备通关，而是规划器的默认优先级与验收门槛。世界里已有更好条件时可以跳过个人非必要物品，但世界硬门槛不能跳。

### 阶段 A：出生与木石工业

1. 用 Copper Axe 砍树，拾取木材和树苗，完成欠种回补。
2. 达到首轮木材阈值，快速合成 Work Bench、平台、墙、木弓/木箭和基础家具。
3. 击杀附近低风险 Slime 获取 Gel；无安全 Slime 时先探索 pots/表面箱获取火把，避免为了 Gel 高死亡循环。
4. 挖石，制作 Furnace、火把和 Campfire。
5. 建初始避难所、三个 NPC 房和两个专属箱；房屋逐室用原版规则验证。
6. 把非随身材料归仓；身上保留平台、火把、治疗和当前目标工具。

成功条件：有安全家、工作台、熔炉、仓库、至少一个空有效 NPC 房、200 平台、基础远程武器与照明。

### 阶段 B：经济、早期洞穴与机动

1. 通过 Slime、pots、箱子和低风险敌人积累至少 50 silver，确保 Merchant 条件真实满足。
2. Merchant 入住后购买 Bug Net；铁/铅不足又急需 anvil 时允许买 Iron Anvil。
3. 扫描表面和洞穴箱，优先：跑鞋、Cloud/Blizzard/Sandstorm in a Bottle 等额外跳、Magic Mirror、Aglet、Climbing Claws、再生/免摔类饰品。
4. 找不到跑鞋则开启钓鱼替代路线获取 Sailfish Boots。
5. 挖铁/铅制作 anvil，挖银/钨与金/铂，制作阶段最优工具、护甲和武器。
6. 寻找生命水晶，提高自动伙伴自己的最大生命；至少 200 HP 后再允许依赖 Goblin Army 自然条件。
7. 用宝石制作钩爪，或在 Goblin Tinkerer 解锁后购买 Grappling Hook。

成功条件：跑鞋等价能力、至少一种额外垂直机动、钩爪或可靠平台能力、金/铂级战斗能力、稳定火把/药水来源。

### 阶段 C：Pre-Hardmode Boss 与关键设施

1. **Eye of Cthulhu**：建短地表多层平台；准备远程/穿透武器、药水和 Campfire。自然条件合适可等待，否则合法制作 Suspicious Looking Eye。
2. **世界邪恶 Boss**：根据 `WorldGen.crimson` 选择 Eater of Worlds 或 Brain of Cthulhu；先取得炸弹/足够镐力和对应召唤条件，使用群伤/穿透策略。目标是邪恶材料与能挖 Hellstone 的镐升级链。
3. **Goblin Army**：满足条件后等待或制作 Battle Standard；完成后全图定位 Bound Goblin，实际走到并解救，购买 Rocket Boots 与 Tinkerer's Workshop，合成 Spectre/Lightning Boots 可用链。
4. **Skeletron**：夜间在 Dungeon 入口对话召唤；建不破坏入口的外部平台场，击败后探索地牢，按装备评分拿 Muramasa、Cobalt Shield、Shadow Key 等有价值目标。
5. **Queen Bee（推荐但非硬门槛）**：发现蜂巢且当前装备收益高时打；不要为可选 Boss 无限耗时。没有幼虫可合法制作 Abeemination。
6. 探索 Underworld，建可持续延伸的长平台桥，规避建筑和宝箱；挖 Hellstone/Obsidian，制作 Molten Pickaxe 与当前最优狱石装备。
7. **Wall of Flesh**：确认 Guide 活着，准备 Guide Voodoo Doll、长桥、治疗、buff 和弹药；在 Underworld 合法投入 lava 召唤并沿单方向作战。击败后由游戏自然进入 Hardmode。

Wall of Flesh 是 Pre-Hardmode 最终 Boss，击败会真实开启 Hardmode，并保证掉落 Pwnhammer；不得直接切 `Main.hardMode`。[Bosses](https://terraria.wiki.gg/wiki/Boss)

### 阶段 D：Early Hardmode 与机械 Boss

1. 立即重新评估避难所周边邪恶/Hallow 扩散和敌人危险；必要时加固，但不进行无限净化工程。
2. 使用 Pwnhammer 合法破坏有限数量祭坛，目标是解锁三档矿；不要为了随机分布无上限砸祭坛。
3. 依次取得 Cobalt/Palladium 镐、Mythril/Orichalcum Anvil、Adamantite/Titanium Forge 与高阶装备；找矿极差时允许通过 Hardmode crates 获取锭作为替代。
4. 获取翅膀或同等级持续空中机动，准备 Greater Healing Potion、buff、弹药和大型平台场。
5. 机械 Boss 默认顺序按现有装备动态选择：有强穿透优先 Destroyer；有强单体和垂直机动优先 Twins；否则 Skeletron Prime。每击败一个都立即评估 Hallowed Bars/Souls 升级。
6. 三个机械 Boss 都要完成；所有三个完成后 Plantera Bulb 才正式可用。[Mechanical bosses](https://terraria.wiki.gg/wiki/Mechanical_bosses)

Hardmode 敌人显著增强，Pre-Hardmode 武器常常不够，进入后必须先补个人装备而不是直接冲世界当前 Boss。[Hardmode](https://terraria.wiki.gg/wiki/Hardmode)

### 阶段 E：Plantera 与 Golem

1. 三机械 Boss 完成后扫描 Underground Jungle 的 Life Fruit、Chlorophyte 与 Plantera Bulb。
2. 优先把自动伙伴独立生命成长到 500 上限，制作 Chlorophyte/Turtle/当前评分更优装备。
3. 在选定 Bulb 周围合法挖出足够大的矩形场地，保留 Bulb 到准备完成；放平台、Campfire、Heart Lantern（有资源时）和检查点。
4. **Plantera**：最后才破坏 Bulb，使用环绕/拉扯策略。Plantera 只会在三机械 Boss 后出现，击败保证 Temple Key。[Plantera](https://terraria.wiki.gg/wiki/Plantera)
5. 用 Temple Key 进入 Jungle Temple；优先拆/避开陷阱，收集 Lihzahrd Power Cell，走到真实 Altar。
6. **Golem**：用 Power Cell 在 Altar 合法召唤；根据房间空间布平台并针对拳头/头/身体阶段作战。

### 阶段 F：Cultist、四柱与 Moon Lord

1. Golem 完成后回 Dungeon 入口，确认四名 Cultist 实际生成。
2. 清理入口空间，但不预先伪造 Lunar Event。
3. **Lunatic Cultist**：识别真身、避开复制惩罚；击败后让游戏自然生成四柱。Golem 后击杀 Dungeon Cultists 才会召唤该 Boss。[Hardmode Walkthrough](https://terraria.wiki.gg/wiki/Guide%3AWalkthrough/Hardmode)
4. **Celestial Pillars**：按当前主武器职业优先击杀能最快带来升级的柱；每柱先杀足够敌人解除 shield，再打柱体。每完成一柱回收 fragments 并在 Ancient Manipulator 合法制作升级。
5. 四柱全部结束后准备 Moon Lord 自动出现；如果战败，收集 fragments 并制作 Celestial Sigil 进行合法重试。
6. **Moon Lord**：Boss 策略依次跟踪两手和头部眼睛，躲避 Phantasmal Deathray，三眼破坏后集中 core；依靠真实机动和场地，不封锁 AI 或锁血。
7. `NPC.downedMoonlord` 为唯一最终完成标志。Moon Lord 是原版最终 Boss，四柱完成或 Celestial Sigil 可召唤。[Moon Lord](https://terraria.wiki.gg/wiki/Moonlord)

### 阶段 G：转换

1. 停止所有自动任务，释放目标、箱子/物品 reservation 和临时场地标记。
2. 写入该世界 `Completed=true`。
3. 保留 profile 的全部物品、名字和外观；清除 `IsAutoRunning`。
4. 重置自动独立生命/魔力覆盖，让普通 `CompanionProfile` 绑定规则接管。
5. 将脑切回普通 `CompanionBrain`，出现在当前安全位置并开始正常跟随主人。
6. 显示本地化完成提示一次；重复加载不得重复刷屏。

官方的抽象进度循环也是“探索新区域 → 用资源升级 → Boss/事件 → 解锁新区域和资源”，目标图应围绕这个循环，而非为每件物品写固定脚本。[Game progression](https://terraria.wiki.gg/wiki/Guide%3AGame_progression)

## 12. Boss 策略接口的最低合同

每个 `IAutoBossStrategy` 必须给出：

- `IsWorldUnlocked`：世界门槛。
- `ReadinessScore` 与缺失能力清单。
- `FindOrCreateArenaGoal`：场地坐标与模板。
- `AcquireSummonGoal`：召唤物/交互/自然召唤路线。
- `TrySummon`：距离、时间、区域和实际消耗验证。
- `ChooseCombatPosition`：随 Boss phase/部位改变。
- `SelectPriorityTarget`：多部位和小怪优先级。
- `HandleFailure`：死亡、Boss 消失、白天、区域离开、召唤物耗尽。
- `SuccessPredicate`：只读世界击败标记，不以“Boss 当前不在”误判成功。

必须有独立策略的原版目标：Eye、Eater、Brain、Skeletron、Queen Bee、Wall of Flesh、Destroyer、Twins、Skeletron Prime、Plantera、Golem、Lunatic Cultist、四柱、Moon Lord。King Slime、Queen Slime、Deerclops、Duke Fishron、Empress、事件 Boss 作为收益驱动的可选策略，不得卡住主线。

## 13. 卡住、失败与无人提问原则

### 13.1 统一任务结果

- `Running`：本 tick 有合法动作。
- `Succeeded`：成功谓词已满足。
- `RetryLater`：天气、时间、NPC、Boss 或掉落的暂时条件不满足。
- `AlternativeRequired`：目标存在但当前路线长期无进展。
- `BlockedMissingWorldResource`：全图确认关键资源不存在且无合法替代。
- `BlockedUnsupportedWorld/Mod`：特殊种子或模组主线没有 provider。
- `Faulted`：代码异常，交给 FaultGuard；连续失败停用该执行通道，不崩游戏。

### 13.2 看门狗

- 移动任务：10 秒没有 24 px 有效进展，局部重寻路；3 次后换入口/目标。
- 采集任务：30 秒没有实际 tile、item 或库存变化，重新验证目标并拉黑 5 分钟。
- 建造任务：同一 cell 12 次失败后标记 obstructed，重新选模板/地点。
- Boss 任务：连续 3 次失败后回到装备与 consumable 评估，至少完成一个真实升级或场地改变才再挑战；若当前阶段已无合理升级，允许继续练习重试，但每次要重建消耗预算。
- 钓鱼目标：20 分钟无目标掉落，挂起并推进其他并行能力。
- 全局阻塞时每 10 秒低成本重新检查世界变化；不弹窗询问用户。

### 13.3 可诊断性

背包顶部或现有 debug overlay 增加：

- 世界阶段 / 个人能力层。
- 当前 Goal → Task → Substep。
- 目标坐标与距离。
- 当前缺少的材料/能力。
- 最近一次真实进展距今 tick。
- 本目标失败次数与下一次重试时间。
- 世界扫描百分比和 CPU 用时。
- 阻塞原因的本地化短句。

日志只在目标切换、阻塞、异常和 Boss 结果时写，不每 tick 刷。

## 14. 模组兼容边界

### 14.1 通用兼容

- 门：现有导航使用 `TileLoader.OpenDoorID(tile)`；自动关闭使用对应 `TileLoader.CloseDoorID(tile)`，因此正确注册 door set 的模组门自动兼容，不写死原版 Door ID。
- 武器/工具：主要看 Item 属性和 projectile 样本；不认识的模组武器先走保守通用评分和现有虚拟 ItemCheck。
- 配方：动态读取已注册 Recipe、recipe group 和 hooks。
- 方块/墙/平台：使用 TileID sets、Item.createTile/createWall 和 ModTile 元数据。
- 箱子：使用 Chest/TileObjectData，而不是只认 `TileID.Containers` 的一个 frame。

### 14.2 不可自动推导部分

模组 Boss 的召唤方式、世界标记、场地、phase、特殊伤害规则和主线顺序无法可靠地从通用 API 猜出。定义扩展接口：

- provider 注册 milestone 和依赖图；
- 注册关键资源定位器；
- 注册 Boss strategy；
- 注册完成标记；
- 可选注册装备评分修正。

没有 provider 时：继续使用模组通用武器/方块/配方，但只推进原版主线；如果模组替换了原版硬门槛导致无法继续，进入 `BlockedUnsupportedMod`。不要通过反射乱猜字段并直接写进度。

### 14.3 特殊世界种子

- 普通种子：正式支持。
- Drunk world：允许 evil/ore 双变体，但目标按当前实际资源动态选择。
- For the Worthy/Master：提高 readiness 与消耗预算，不改变合法流程。
- Remix/Zenith（含 Mechdusa 差异）、No Traps、Not the Bees、Celebration、Constant 等：首版若没有专门 adapter，明确阻塞并显示原因。尤其 Zenith 的机械 Boss 路线不能套普通三 Boss 分开召唤。

## 16. 实施顺序（必须分阶段编译）

### Phase 1：身份与空脑

- 新书、九语言、唯一 profile/world 绑定、右键背包。
- 新建自动身份标记和空的 `AutoCompanionBrain`，只会安全 idle。
- 普通指挥/建造/小队/护驾过滤自动身份。
- 玩家互伤隔离和 1s/5s 复活。
- 编译、HJSON 解析、存读档、世界切换测试。

### Phase 2：合法资源闭环

- 自动专用世界掉落拾取。
- 砍树/补种、挖石矿、库存整理、自有箱子。
- 动态合成服务。
- 避难所和房屋验证。
- Merchant、Bug Net 与基础购物。
- 此阶段必须能从铜镐/铜斧独立做到房屋、炉、砧、金属装备。

### Phase 3：知识与导航

- 分帧扫描、兴趣点缓存、跨区域导航、危险 tile 成本、任务看门狗。
- 宝箱目标、跑鞋搜索、生命水晶、矿簇。
- 不允许用瞬移掩盖跨世界导航未完成。

### Phase 4：钓鱼替代

- 全局水体缓存、bait 链、鱼竿、真实抛竿、crate 打开、跑鞋停止谓词。

### Phase 5：Boss 框架和 Pre-Hardmode

- Boss strategy 接口、装备 readiness、场地模板、召唤、失败恢复。
- Eye、evil boss、Goblin、Skeletron、Queen Bee、Wall。
- 完成从新世界到 Hardmode 的长时间实测。

### Phase 6：Hardmode 到结局

- 三档矿、翅膀、三机械、Plantera、Temple/Golem、Cultist、四柱、Moon Lord。
- 完成转换与重复加载稳定性。

### Phase 7：兼容与性能

- 模组物品/配方/门/方块通用验证。
- 特殊种子 fail-closed。
- 大世界扫描帧耗、长时间内存、异常通道和自动测试。

每个 Phase 都要先 `dotnet build MoreAIPlayer.csproj --no-restore -p:BuildMod=false -p:TargetFramework=net8.0 -v:minimal`，再做 HJSON 全量解析和 `git diff --check`。源码编译通过不等于实机流程通过。

## 17. 验收清单

### 17.1 自动关门（本轮小修）

- 伙伴只关闭自己成功打开的门。
- 整个身体走过后才尝试关闭。
- 玩家/NPC 仍在门洞时不强关，稍后重试。
- 主人、机关或别的伙伴打开的门不被误关。
- `TileLoader.OpenDoorID/CloseDoorID` 注册正确的模组门可用。
- Vanilla Tall Gate 可开可关。

### 17.2 自动书

- 九语言无缺键、无过期说明。
- 左键最多一名；重复左键不动位置、不改血、不改装备、不换名字。
- 右键准确打开该 profile 背包。
- 世界重进、角色切世界、mod reload 后不会串 profile 或复制物品。
- 多人入口 fail closed，不留下 synthetic player slot。

### 17.3 独立性

- 主人在地图另一端、受伤、死亡、放路点、切模式、开建造战术，都不影响自动伙伴目标。
- 自动伙伴与玩家双方互不造成伤害。
- 自动伙伴不拿主人背包和非自有储物箱材料。
- 通关转换后上述普通伙伴功能全部恢复。

### 17.4 合法流程

- 新世界只靠铜镐/铜斧完成木石、房、炉、砧、Merchant 和早期装备。
- 每次砍树都有补种尝试。
- 没有跑鞋箱时能转钓鱼；有跑鞋时不浪费时间钓鞋。
- 不凭空增加任何物品；长时间库存审计满足输入 + 掉落/箱/购买/合成 = 输出 + 消耗。
- 每个 Boss 都由合法召唤或世界事件产生，成功只认世界标记。

### 17.5 生存和卡住

- 普通死亡 60 tick、Boss 在场 300 tick。
- 触发陷阱后下一 tick 有规避输入；没有物理可行解时仍会受伤而不是无敌。
- 目标被玩家挖走、箱子拿空、房屋拆除、关键物品被从背包取走时不崩溃，能重规划。
- 找不到资源/不支持种子时进入明确 Blocked，不写假进度、不刷屏、不询问用户。

### 17.6 性能与稳定性

- 大世界扫描不出现单帧完整遍历。
- 无目标世界掉落不会造成每个物品一次 A*。
- 运行 2 小时知识缓存、拉黑表和日志不会无界增长。
- 任一模组物品 hook 抛异常时只停用当前通道或自动伙伴，不劫持 `Main.myPlayer`、相机或其他伙伴。

## 18. 不要做的“捷径”

- 不要自动给一套阶段装备。
- 不要在世界阶段变化时刷新 loadout；装备必须实际获得。
- 不要直接 `NPC.SpawnOnPlayer` 绕过召唤物和区域条件。
- 不要直接修改箱子后声称伙伴走过去拿过。
- 不要为全图目标每 tick 跑 A*。
- 不要用普通伙伴远离主人传送策略给自动伙伴做跨图移动。
- 不要把所有 Boss 用同一个“保持距离并自瞄”通用策略糊过去。
- 不要因为网页攻略列了某件装备，就让 planner 只认该 ItemID；以能力谓词和实际配方/世界变体为准。
- 不要声称“支持所有模组自动通关”；没有 progression provider 就明确降级。

最终原则：**让它像一个知道全部规则、反应快得离谱的真实玩家，而不是一个披着玩家皮的世界编辑器。** 允许它卡住，必须让它可诊断、可恢复、可继续迭代；绝不能用隐藏作弊把“自动通关”伪装成已经完成。
